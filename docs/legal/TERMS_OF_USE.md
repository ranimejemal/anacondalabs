## 2. What AegisLab is

AegisLab is a security testing tool that sends non-destructive HTTP
requests to an API you configure, to check for common vulnerabilities
mapped to the OWASP API Security Top 10, and separately scans source code
you upload for hardcoded secrets and missing security middleware. It is
provided for legitimate security testing of systems you own or are
authorized to test.

## 3. Authorization — read this carefully

**You must only run AegisLab's scans against APIs and systems you own, or
that you have explicit, documented authorization to test.** Running
security scans against systems without authorization may violate the
Computer Fraud and Abuse Act (US), the Computer Misuse Act (UK), or
equivalent laws in your jurisdiction — regardless of whether the scan
itself is "non-destructive."

This is not just a formality: the app itself requires you to explicitly
check a confirmation box (`confirm_authorized`) before any scan will run
against a live target, and this checkbox exists specifically so there's no
ambiguity that you attested to having authorization at the moment you ran
the scan.

**You are solely responsible for ensuring you have proper authorization
for every scan you run.** [Company/Developer Name] is not responsible for
any consequences of running AegisLab against systems you weren't
authorized to test.

## 4. No warranty

The Software is provided "AS IS," without warranty of any kind, express or
implied. Specifically:

- **AegisLab does not guarantee it will find all vulnerabilities in your
  API or codebase.** A clean scan result is not a certification of
  security — it means the specific checks AegisLab currently runs (see
  the README's coverage table) didn't find an issue, not that no issues
  exist. AegisLab intentionally does not cover every OWASP API Security
  Top 10 category (see README §"Coverage status").
- AI-generated fix suggestions (where you opt into that feature) are
  generated by a third-party AI model and may be incorrect, incomplete, or
  inappropriate for your specific codebase. **Review every AI-suggested
  fix before applying it** — this is explicitly why "Auto-apply" hands you
  back a modified copy to review, rather than patching your live
  repository directly.
- Even non-destructive security scans can, in rare cases, have unexpected
  effects on a target system (e.g. triggering rate limits, alerting
  monitoring systems, or interacting poorly with a fragile staging
  environment). Test against production systems at your own risk, and
  consider testing against a staging environment first.
